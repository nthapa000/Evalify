# Evalify test papers — basic science

Generated by `python eval/make_test_papers.py`. Print on A4 at 100 % (no "fit to page").
**Rule for every paper: students write only the final answer** — option letter(s) or the value.
Rough work goes on a separate rough sheet, which is not evaluated and not photographed.

| Set | Print | Planned sheets | Students write |
|---|---|---|---|
| OMR | `omr/omr_question_paper.pdf` (20 Q, 14 single + 6 multiple correct) + one of `omr/omr_layout_{1,2,3}.pdf` (PNG also provided) | 5 per layout = 15 | fill bubble(s) |
| Handwritten MCQ | `mcq/mcq_question_paper.pdf` (10 Q, single + multiple correct) | 15 | `1. B`, `2. A, C` on plain paper |
| MCQ + numerical | `mcq_num/paper_2{A,B,C}_question_paper.pdf` (2 MCQ + 3 numerical) | 5 per paper = 15 | `1. B`, `4. 2500 m` on plain paper |

Answer keys: `keys/answer_keys.pdf` (to read) and `keys/*.json` (Evalify paper format; numerical
answers carry a tolerance and unit, so `2.5 km`, `2500 m` and `2500` all match a key of 2500 m).

## Edge cases to include on purpose

Spread these over the sheets (each case on 2–3 sheets is enough). They are what broke the readers on
real data.

**Handwritten MCQ**
- a letter **struck out and rewritten** (~~B~~ C) and one **overwritten** letter
- an unusual **D** (like "Ɗ" or circled), lower-case letters (`c`, `a`)
- a [one or more correct] question answered with **two or three letters**, in any order (`C, A`)
- one **blank** question, and answers written **out of order** (Q7 before Q3)
- a **wrong** answer on purpose on several sheets (so not every sheet scores full marks)

**MCQ + numerical**
- equivalent forms: `5/8` vs `0.625`, `1/2` vs `0.5`, `2.5 km` vs `2500 m`
- negative value (paper 2B Q4 is −7 °C): write it with and without the unit; one sheet **without the minus sign**
- a **plausible wrong** value on purpose (e.g. `0.65` instead of `0.625`, `19.8` instead of `19.6`) —
  this checks that no reader silently "corrects" it
- a value **struck out and rewritten**, one **blank**

**OMR**
- one **light pencil** fill, one **erased and refilled** bubble, one **half-filled** bubble
- [one or more correct] questions filled with **2–3 bubbles** (correct and incorrect sets), and a
  **double fill on a single-answer** question (must score 0)
- one **blank** question per sheet on a couple of sheets
- fill the roll-number grid on layout 1 (it must be ignored by the answer reading)

## Photographing

- Mostly **phone photos** (whole page visible, all four corners in frame): some straight on, some at an
  angle, one or two with a shadow or uneven light. A couple of flatbed scans for comparison.
- One image per page, JPG or PNG. File name: `<set>_<sheet>_p1.jpg`, e.g. `omr_L2_s03_p1.jpg`,
  `mcq_s07_p1.jpg`, `2B_s04_p1.jpg`.

## Labelling (what the student actually wrote — not the key)

Each `labels/*_labels.csv` already has one row per planned sheet (sheet id + photo file name filled in;
name your photos to match, or edit `photo_file`). Open it in Excel / LibreOffice / Google Sheets and fill:
- MCQ / OMR columns:

  | On the sheet | Type in the cell |
  |---|---|
  | one answer | `B` |
  | multiple answers | `A,C` / `A,B,D` (any order; `AC` or `A C` also accepted) |
  | blank / not answered | leave the cell **empty** |
  | struck out and rewritten (~~B~~ C) | the **final** answer `C`, and note it in `edge_cases` |
  | genuinely unclear (you cannot tell what was meant) | `?` — correct outcome is "send to a TA" |

  In Excel / LibreOffice / Google Sheets just type `A,C` (the app quotes it when saving). In a plain
  text editor write `"A,C"` (with quotes) or `AC`.
- Numerical columns: copy the value exactly as written, including the unit, e.g. `2.5 km`, `5/8`, `-7 °C`;
  empty if blank, `?` if unreadable.
- `edge_cases`: which tricks are on this sheet (e.g. `Q3 struck B→C; Q5 blank`).
- OMR: the `layout` column is pre-filled (1, 2 or 3) from the sheet id.

Put the photos and filled CSVs in one folder and tell Claude; an import script will turn them into an
eval set (`eval/data/own_<set>/manifest.jsonl`) for the bake-off, OMR and end-to-end runs.

## Checked before printing

The template OMR learned all three layouts (20 questions × 4 options, numbered from the printed labels,
roll-number grid ignored) and read 20/20 answers back from a simulated phone photo of each, including a
light-pencil fill, a double mark and a blank.
